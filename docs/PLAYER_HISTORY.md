# 玩家历史明细

入口：后台「玩家与积分」中每位玩家的「历史明细」，或页面右上方「查询玩家历史」。支持按昵称、Telegram用户名（可带@）、TG ID或账户ID搜索，最多显示20个匹配玩家，结果过多时需缩小搜索。

详情页显示当前余额、可用积分、冻结积分，并提供三类记录：

- **历史下注**：下注时间、期号、英雄位置/名称、单笔本金、中奖/未中奖/流局/待结算、实际盈亏、结算时间。同一期多笔下注分别展示。结果与金额读取当时已保存的注单，不用当前赔率重算。0倍中奖仍显示中奖，盈亏为0；待结算不显示为未中奖。
- **积分流水**：入账时间、上分/下分/游戏盈亏、来源（玩家申请获批或后台人工操作）、变化量、变化后余额、关联期号和备注。历史手续费类型仍如实展示，盈亏按当时的净变化保存值展示。
- **上下分申请**：申请时间、类型/金额、待审批/已批准/已拒绝、处理时间、申请时余额和审批备注。申请不代表已经入账；以批准后的积分流水为准。后台直接调分没有玩家申请记录，仍可在流水中查到。

所有时间为北京时间。日期包含开始和结束当天：下注按下注时间，流水按入账时间，申请按申请时间筛选。金额显示三位小数；每页25条，按时间和唯一ID倒序，使用游标分页；查询期间新入账或结算可能更新结果，需点查询重新读取最新状态。不是一个跨多页锁定的历史快照。

后端接口均要求管理员认证：

```text
GET /api/player-search?q=昵称或用户名或ID
GET /api/player-history?account_id=tg:111&view=bets&limit=25
```

`view`可选bets/entries/requests。`filter`在bets下为WIN/LOSS/VOID/RESERVED，在entries下为CREDIT/DEBIT/GAME，在requests下为PENDING/APPROVED/REJECTED；空值表示全部。`from`、`to`为YYYY-MM-DD，`cursor`使用上一页返回的`next_cursor`。每页1至100条，返回account/rows/next_cursor；无下一页时游标为空。缺失玩家400，不存在或非玩家账户404，日期/筛选/游标无效400。

新增按玩家、时间、ID的下注/流水/申请索引，首次启动建立；不更改数据库版本6、金额单位或历史账目。接口优先使用独立只读审计连接，分页不统计全量COUNT、不加载整期逐笔结算JSON。查询不产生账目、审批或Telegram消息。
