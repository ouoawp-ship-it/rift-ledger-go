# 当前玩家模式（2026-09）

当前生产服务使用玩家模式：不创建或显示群主/运营方账户、独立费用账户，也不扣取下注费用。玩家下注冻结本金与本期各庄家牛型失败净亏损倍数中的最大风险；结算时赢分直接增加玩家余额，输分按实际庄家牛型对应倍数扣减，流局游戏盈亏为零。赔率为0至100倍、最多两位小数。余额、下注、上分下分、冻结和流水均精确到0.001积分；每笔盈利或亏损按本金乘对应倍率计算，超过三位小数时四舍五入到第三位，再汇总入账。例如33×1.2=39.600，10.005×1.23=12.306。输入金额超过三位小数直接拒绝。后台“今日盈亏”按当天玩家游戏盈亏的相反数计算。

数据库版本3使用整数千分之一积分存储金额，接口仍以积分为单位。首次启动会在事务中将版本1/2的整数金额等值转换（1000显示为1000.000），不会重算历史结算、改写历史结果或重复执行旧业务请求。迁移失败会整体回滚；已升级的库不能直接交给旧版本程序运行。

以下旧规则段落仅用于解释历史数据库中的旧期次快照，不适用于新生产期次。

# 规则定义与首版限制

## 权威依据及变化范围

业务参考既有的《CODEX_TASK_V9_实施朱雀式WinForms界面与新账本规则.md》第2节与第5节，以及V5中的伤害与比较定义。当前每个庄家牛型均可单独设置闲家失败净亏损倍数，默认1倍；不会重新启用旧按期收费或按庄家倍率扣玩家本金。

这不是旧软件数据库迁移。Go0.1.0只使用自己的新库与规则快照。四位前置1、零组合开关、庄家流局整期流局、只支持整数积分等在页面明确展示，首次操作需核实。

## 伤害规范化

| 原始输入 | 处理 | 例子 |
|---|---|---|
| 三位 | 该英雄流局 | 999不是没牛 |
| 四位 | 前置一个1 | 2745→12745 |
| 五位 | 不变 | 12745→12745 |
| 六位 | 取末五位 | 100001→00001 |

输入为3至6个ASCII数字，首位不能为0。计算保存原值与规范化字符串；不是转整数后把零丢掉。四位增加的1放在哪个位置不影响本版牌型/最大数字比较，因为这两个算法只依赖数字集合；仍保存明确的规范化形式供审计。

五位选三：若任意三个数字之和%10=0，剩余两数之和%10得1—9或0(牛牛)。零组合可由规则禁止；没有组合时没牛。等级0与等级10独立，不能都存余0。提供凑牛位置与剩余数字便于验证。

五个英雄中非庄家三位伤害，只使该位置的注单VOID，其他正常比较；庄家三位则全局VOID。五个原始伤害必须按规则有效录入。无通用“强制流局”按钮。

## 胜负与费用

player.rank > house.rank即赢；等级相同仅比较最大数字，更大才赢；最大数字相同庄赢。倍率不参与胜负判断，也不比较总伤害。默认倍率对应等级0..10为[1,1,1,1,1,1,1,2,2,3,4]，每项可单独改成1..100整数。

对本金B：赢=+B×闲家自身牛型倍率；输=-B；流局游戏变化0。费用每笔≤100为1，>100为2。费用时点可选受理或结算，VOID可选择退费/不收或保留；费用账户为fees或house。零本金、超限、余额不足、重复请求都不新收费。

未确认配置禁止开盘。设置新模板不改已开盘期次的快照。用户的开盘确认锁定全部规则。修改模板只影响下一次开始的期次。

## 资金、冻结与25%限制

V0.1.0的积分和倍率都用int64，账户额度上限1,000,000,000,000。单笔本金配置上限1,000,000；每期最多10,000笔是防误操作保护，不代表承诺该负载的实时性能。

累计本金上限采用本期接受时的账面余额基数，受理已扣掉的本期费用加回该基数；不会反复把“扣去冻结后的可用余额”除以4。已登记人工加减分会影响可用基数，减分不得破坏既有冻结或累计比例；这不是固定开盘余额快照。没有跨期未结算下注，因为服务只允许一个活动期。

受理时收费：玩家冻结本金，费用立即双边转入收款账户；若VOID政策允许退费，收款账户同时保留退款准备，不能提前花掉。结算时收费：玩家冻结本金+费用，结算才实际扣费。

运营方保守冻结每笔本金×本期最高倍率；实际发生赢单时按该玩家实际牌型支付。即使某个低牛型赔率被调得更高，最大承付也随真实表变化。释放冻结、游戏转账、费款/退费、结果落库和待发消息同一事务成功或失败。

资金流是双边记账：每个batch两笔entry，金额合计0。人工上下分对应external清算账户，费用属于FEE/FEE_REFUND，游戏属于GAME，调分为ADJUST；没有把本金解冻再当成一次返还。

## 期次与消息

DRAFT→OPEN→CLOSED→SETTLED或VOID；保存英雄不等于开盘。结算后原子生成下一期DRAFT，未选英雄未选庄，不自动开盘。期号为真实日期+4至8位序号，自动续期保持日期前缀、序号+1；跨日可在下一期草稿配置时手改，不自动把历史归到新日期。

结算前使用预览hash，伤害、规则或注单修订变化导致原hash失效。最终结果不可重写；已经结算相同输入重试返回已有结果，不重复加减分。

消息重试不调用结算。群期次卡片更新不是账本事务的一部分，网络失败不撤销已接受下注或已结算结果。未知送达状态需人工核实；该会话后续发送暂停，其他会话可继续。
