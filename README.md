# 峡谷账房 · Go 服务端 V0.1.0

**新服务器部署请优先阅读：[服务器首次部署与日常更新](docs/QUICKSTART.zh-CN.md)**。包含 GitHub SSH 授权、一键安装、Windows 访问、机器人配置、更新与备份命令。

用于人工录入英雄联盟对局伤害，计算牛牛、比较庄闲、记录注单与账目。Go 业务核心、中文网页管理、SQLite 持久化、可选 Telegram 私聊入口，部署在 Linux 服务器上，不需要 Windows 桌面程序保持运行。

**这是新开发的独立服务端首版，不是旧 C# 项目的已验证完整移植。没有改动、导入或重算原来的 C# 数据。** 当前交付源码、测试、配置与部署文件；没有实际登录你的服务器，也没有使用真实机器人 Token 联调。

## 一、已经包含

- 独立伤害计算器：原始数字、五位规范化结果、凑牛三数、余数、牛型、最大数字及对庄理由。
- 期次：手填期号、五个唯一敌方英雄、手选庄位、开盘、封盘、预览、确认结算、自动下一期空草稿。
- 账本：白名单、人工上下分、累计25%限制、玩家本金冻结、玩家游戏盈亏流水和只读对账。玩家模式不建立运营方或独立费用账户。
- 规则：11项独立盈利倍率、每期规则快照；玩家模式不收手续费。
- Telegram：私聊快捷下注、个人中心、三日流水摘要、自己的注单、历史开奖、联系管理员；群消息按钮、同一期卡片更新。
- 运行：管理员密钥鉴权、持久幂等键、消息队列、重复 update 去重、发送未知状态人工核验、优雅退出与同目录单进程锁。

网页页面：本期控制、玩家与积分、上下分请求、赔率设置、历史与流水、发送记录、英雄数据、机器人设置、伤害计算器、运行检查。界面使用墨白配色、分组导航和响应式表单，没有单独的前端安装或打包步骤。

## 二、推荐的服务器启动方式

以下命令在已安装 **Docker Engine 与 Compose 插件** 的 Linux 服务器执行。首次构建需要访问 Go/Debian 镜像与 Debian 软件源。这里不提供会覆盖服务器原有服务的自动安装脚本。

```bash
unzip rift-ledger-go-v0.1.0.zip
cd rift-ledger-go
bash scripts/init-env.sh
nano .env
# 填写配置；不启用 Telegram 时，所有 TG 字段保留空值或0。
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 app
```

`init-env.sh` 随机生成64位管理员密钥，拒绝覆盖已经存在的 `.env`。不要用示例密码，不要把 Token 发到群里。Docker 配置将宿主机入口限制为 `127.0.0.1:8080`，不会默认将管理后台裸露到公网。

### 从你的 Windows 电脑打开网页

在 Windows PowerShell 执行，将登录用户和服务器IP换成你的实际值：

```powershell
ssh -N -L 8080:127.0.0.1:8080 登录用户@服务器IP
```

保持此窗口连接，在本机浏览器打开 `http://127.0.0.1:8080`。输入服务器 `.env` 里的 `ADMIN_TOKEN`。浏览器只在本页面内存保留该值，不使用 localStorage/sessionStorage；刷新页面需重新连接。

本机8080被占用时，改成 `ssh -N -L 18080:127.0.0.1:8080 登录用户@服务器IP`，打开本机18080。如果你修改了 `.env` 的 `HOST_PORT`，隧道右侧也相应修改。

需要域名时，在服务前配置受你管理的 HTTPS 反向代理；不要直接开放8080明文后台。V0.1.0只有一个管理员密钥，不具备多人管理员账号、角色权限和登录审计到个人的能力。

## 三、Telegram 配置

```dotenv
TG_BOT_TOKEN=在你自己的服务器填写真实机器人Token
TG_BOT_USERNAME=机器人用户名不带@
TG_GROUP_ID=-100xxxxxxxxxx
TG_ADMIN_ID=通知管理员的个人Telegram数字ID
TG_SUPPORT_USERNAME=联系管理员用户名不带@
```

这些行展示字段含义，不要原样照抄占位文字。群 ID 为负整数，管理员 ID 为正整数。机器人必须有目标群发消息权限；需更新本期卡片时，不要手动删除该卡片。

先让管理员和测试玩家私聊机器人 `/start`，再测试通知。禁止普通成员发言、群内消息保留等群权限，请在 Telegram 中人工设置；本版不自动修改群权限，不保证阻止用户删除消息。

**同一个 Bot Token 不能同时交给旧 C# 接收器和这个服务。** 正式切换前先妥善完成旧系统活动期、备份并停止旧接收器。Go 服务使用长轮询；发现已有 webhook 或收包冲突会报告错误，不会擅自删除 webhook、清掉待处理消息或抢占旧程序。

未知玩家私聊会留下真实ID、提示尚未加入，并在配置了管理员ID时通知管理员。开通资格在网页操作，不自动赠送积分。支持 `1.100`、`1 . 100U` 等整数本金格式；庄位不可投，封盘后只查询。私聊消息被删除/编辑不会修改已受理注单。

开启 Telegram 前请使用干净的正式数据卷。**不要把隔离演示库接上正式机器人**：演示中的结算也可能留下待发送私聊通知。

## 四、第一次使用顺序

1. 打开「规则设置」，核对11项盈利倍率和零组合口径并保存。玩家模式不配置扣费时点、流局费用或费用归属。
2. 打开「玩家与积分」，录入真实 Telegram ID 并开通。人工登记玩家积分；玩家模式不需要运营方承付账户。
3. 在「本期控制」手填首期期号，如 `2026-09-20-0001`，创建草稿，填写实际敌方五英雄的稳定ID与名称，明确选择庄家。保存后尚未开放下注。
4. 点击「开始答题」。玩家私聊机器人下注。点击「停止答题／封盘」后，不再受理新单。
5. 录入五个原始伤害，生成预览，检查每个牛型和逐笔玩家盈亏，再确认结算。
6. 成功入账后自动生成下一期空草稿，英雄和庄位清空，不会自动开盘。发送情况与账目状态分别查看；不要为补发消息重复开奖。

英雄ID为人工填写的稳定标识，例如 `Aatrox`；本版未加载完整英雄图库，不能自动识别是否真的属于敌方。程序也不读取游戏客户端、截图或 Riot 战绩。封盘由管理员操作，不自动检测二塔或投降。

## 五、本版规则摘要

三位伤害为该英雄流局，不是没牛；四位增加一个数字1（实现为前置）；五位不变；六位截后五位并保留零。原始输入不要补零，少于三位、多于六位以及非整数输入拒绝处理。

五位中任选三个数字，和可被10整除则成牛，剩下两个数字的和取个位；余0为牛牛，否则为牛1—牛9。无合法三数组合为没牛。是否允许0+0+0在首次配置时明确选择；本版无炸弹牛、五小牛等特殊规则。

比较先看牛型，再看最大一个数字，仍相同庄赢，不比第二大数字，也不比较原始总伤害。

默认净盈利倍率：没牛至牛6为1，牛7/牛8为2，牛9为3，牛牛为4。赔率支持0至100倍、最多两位小数；闲家获胜按自身倍率计算并四舍五入为整数积分，失败只亏本金1倍。玩家模式不收取费用，获胜余额直接增加。

三位伤害使该英雄流局，庄家英雄流局时整期流局；本版不再录入对局时长。未确认的边界通过首次规则确认呈现，不把旧测试选项假定成生产决定。详细定义见 `docs/RULES.md`。

## 六、备份、升级和停机

```bash
bash scripts/backup-docker.sh    # 一致性备份 + integrity_check
# 将 backups 中的备份加密后保存到其他机器。
# .env不在数据库备份里，请另行安全保管。

docker compose stop            # 正常停止，不删除数据卷
# 更新源码之前先备份并妥善处理活动期，之后：
docker compose up -d --build
```

**不要执行 `docker compose down -v`，它会删除数据卷。** 不要在服务运行时只复制主 `.db` 而漏掉 WAL；使用附带备份脚本。恢复必须先停写、保存故障现场、验证备份，并确保数据库、WAL与SHM来自一致状态；具体恢复说明见 `docs/DEPLOY.md`。

只支持单进程、单运营方、单群、单活动期。数据库必须在本机磁盘，不能放NFS共享目录或多个容器并发消费同一机器人。不要直接修改SQLite账目；已结算结果不能覆盖。本版尚无独立的作废/冲正审批工作流，也没有按玩家的大额特批流程。

## 七、不用 Docker 的运行方式

Linux 主机安装 Go、C编译器与 SQLite 开发库后：

```bash
# Debian/Ubuntu的编译依赖，Go需另行安装：
sudo apt-get update
sudo apt-get install -y build-essential libsqlite3-dev sqlite3 ca-certificates tzdata
bash scripts/init-env.sh
bash scripts/run-local.sh
```

常驻服务可使用 `deploy/rift-ledger-go.service`，步骤见 `docs/DEPLOY.md`。所有业务代码是Go；SQLite使用一个小型 cgo 绑定，因此不能直接 `CGO_ENABLED=0` 编译，运行机器需要相容的 `libsqlite3`。推荐在目标架构/系统或所附Docker环境中编译，不混用不相容的动态库。

## 本轮运维与后台功能

首次部署（Ubuntu 24.04、x86_64）：

```bash
git clone <你的私有仓库地址> /opt/rift-ledger/rift-ledger-go
cd /opt/rift-ledger/rift-ledger-go
./scripts/install.sh
```

`install.sh` 会安装 Docker 官方 apt 仓库中的 Docker Engine/Compose plugin（不会执行不可审计的远程脚本），创建 `data/`、`backups/`，初始化 `.env`，构建并等待 `/healthz`。已有 `.env`、数据库和运行配置不会覆盖。后台通过 `http://服务器IP:8080/` 访问；公网使用时应在防火墙限制管理来源，并在反向代理后启用 HTTPS。

后台“机器人设置”可保存 BotFather Token、机器人用户名、群 ID、管理员 TG ID 和客服用户名。Token 只显示掩码；保存会先备份并原子替换 `data/runtime-settings.json`，随后服务自动重启并立即应用最新设置。可单独测试 `getMe`，测试群发送必须人工点击。运行配置优先级为：运行配置文件 > `.env` 初始值；`.env` 只用于第一次启动配置。

陌生用户私聊会按 Telegram ID 建立待确认账户，并保存用户名、姓名和联系时间。支持 `查`、`查询`、`余额`、`上分100`、`上分 +100`、`下分100`、`回100`；上分申请可以先提交，管理员在“上下分请求”批准或拒绝，批准上分时自动开通玩家资格，并复用统一双边账本保留流水。下分仍要求账户已经开通且可用积分充足。同金额待处理申请不会重复建立，Telegram 管理员通知失败不影响申请主事务。客服关键词为“客服 / 联系管理员 / 联系 / 人工 / 管理员”。

“英雄数据”使用 Riot Data Dragon 官方版本和图片缓存，支持中文/英文名称搜索，刷新失败保留旧缓存；五英雄顺序、庄位和媒体组发送都走发送队列，图片失败会降级为纯文字。页面保留 Riot 法律声明和运营者合规责任，正式上线前请完成 Riot Developer Portal 注册与政策审核。

以后更新和备份：

```bash
cd /opt/rift-ledger/rift-ledger-go
./scripts/update.sh
./scripts/backup.sh
./scripts/health-check.sh
```

`update.sh` 先 `git fetch`、检查分支、`git pull --ff-only` 和数据库备份，再构建并健康检查；不会删除 volume 或执行 `down -v`。不要提交 `.env`、`data/`、`backups/`、`runtime-settings.json`、Bot Token、ADMIN_TOKEN 或数据库。


### 玩家结算模式

当前运行模式为玩家独立结算：新服务启动时会删除空的 `house` 和 `fees` 账户，玩家赢分按固定赔率直接增加余额，玩家输分按本金扣减，不收手续费。后台“玩家与积分”只显示玩家 TG ID、昵称、用户名、余额、本期下注、下注内容和上期盈亏，并显示玩家数量、玩家总分和今日盈亏。今日盈亏定义为玩家游戏流水合计取反：玩家总体亏损1000显示盈利1000，玩家总体盈利1000显示亏损1000。已有 `house` 或 `fees` 非零余额/历史流水时，服务会拒绝自动删除并提示先迁移，避免误删账目。
